## What is 'batteries included'?
A 'batteries included' web framework comes with most of the things you will really need to build a web app.
For most web apps it's the right way to build.

## When is 'batteries included' good for you?

You are building a type of app that is aligned with the the use case of the framework. Additionally you are aligned with the
development philosophy / style facilitated by the framework. 

As such you need to use the right web framework to build a web app. When that is the case you get plenty of benefits.

### 1. Common architectural patterns
Your web app makes use of architectural patterns required in web apps. 
This might include:
1. Persistence
2. Presentation (ie. MVC)
3. Security
4. Static content
5. API's
6. OOP patterns (like Factory, Singleton, etc.)
7. Code organisation into modules / folders
8. Configuration
9. Documentation
10. Dependency management
etc. 

The framework has these things already built in. As such it makes it really easy to structure you app with these patterns. 
This makes dev team more productive as it can focus most of it's time on building features.

### 2. Common foundational features
Common foundational features are generic features that most apps use as part of the "plumbing" of the system.

Common foundational features provided by a web framework include:
1. ORM for persistence (ie. Active Record)
2. Presentation (ie. MVC with specific view templating)
3. Security - Authentication & Authorisation (ie. users & users permissions), user session, etc.
3. REST & GraphQL for API's
4. Jobs (ie. cron jobs for one off or recurring tasks)
5. Static content offloaded to CDN
6. Caching
7. Queues
8. Logging
9. Metrics
etc.

In practice it means that the developper already has 90% of the feature implemented in the framework & needs to write 10% of code that 
customises some behavior to his specific uses case. Often this is simply a configuration file & a couple of lines of code.

This helps the dev team deliver features faster as there is less "plumbing" to take care of. 

### 3. Common devops features
The dev & release process consists of a succession of steps that are common across all webb apps. 
A good framework can provide ready made "recipes" for them:
1. Building
2. Environment configuration
3. Testing - QA & integration
4. Packaging & deployment
5. Data migration & backups

Typically these recipes are well implemented & follow best practices. This accelerates the dev team delivery speed as there is less
"devops" complexity to take care of.


### What are the benefits?
1. Common mindset & language across dev team : simpler communication, onboarding, etc. - you can grow the team easier / faster
2. Fewer decisions on micro architecture & common tasks - free up mental bandwidth for other things
3. Less effort for common tasks (as the framework makes it easy for you) - you are more productive
4. Higher delivery quality (as the framework does the heavy lifting - security, packaging, etc.) - less bugs end up in production (especially on critical stuff like security)


## What does 'batteries included' require from you?

### 1. Invest time
You need to invest time upfront to read the documentation of the frameowork & understand it's philosophy and way of doing things.
Over time the framework will change so you need to keep up.

### 2. Ready to compromise
Frameworks are opinionated beasts. They have to be to give you speed & flow. You need to make sure that your development philosophy
is mostly aligned with the framework. In some cases you won't get full alignment. When that happens you might have to
compromise on your end & follow the way of the framework.


## What are the limitations?
### 1. Type mismatch
Given enough time an app can change quite a bit. For example you started with a typical web app but in a couple of releases real time
features become more and more important (ie. trading, chat, etc.). These differences can accumulate over time and as such the web framework
you started with becomes less and less valuable.

### 2. Philosophy mismatch
Frameworks tend to be very opinionated about everything in your app development (ie. micro architecture, code style, macro architecture, devops, etc.). 
When your development philosophy is not aligned with the framwork then you will lose most benefits as you fight the framework's ways of doing things.


## Two "batteries included" web frameworks

### 1. Phoenix - the Elixir web framework

[Phoenix Framework](https://www.phoenixframework.org/) is "the web framework" for the Elixir ecosystem. There are
no real quality alternatives in the ecosystem. Basically it's the Ruby on Rails for Elixir.

The framework was designed based on the Ruby on Rails philosophy. The main contributors had extensive experience
(and some dissapointments) with RoR.

![Phoenix](./phoenix-logo.png 'Phoenix logo')

#### PRO's
- [Open source](https://github.com/phoenixframework/phoenix/blob/main/LICENSE.md)
- [Well documented](https://hexdocs.pm/phoenix/Phoenix.html) & [Online courses](https://pragmaticstudio.com/courses/phoenix-liveview) available
- Wide scope (ie. standalone apps, web apps, amazing realtime support)
- Battle tested & large community
- Core features included (ie. security, persistence, API, etc.)
- Architectural patterns included (modularity, dependency injection, OOP patterns etc.) 
- Devops ready : testing, deployments, data migration, etc.
- Good choice for projects of any size

#### CONS
- You need to like functional programming
- You need to learn Elixir (which is very different from Ruby or TS/JS)

`youtube: https://www.youtube.com/watch?v=MZvmYaFkNJI&t=2s`


### 2. NestJS - a great Jamstack web framework

The Jamstack ecosystem is pretty fragmented. For most tasks there are several "standard ways" of doing things (and libraries).
This is damaging for dev productivity & overall dev experience (and sanity). It's exactly the opposite from the Ruby & Rails ecosystem.

During the last several years we started to have some good options for 'batteries included' web frameworks in Jamstack as well.

![NestJS](./nestjs-logo.png 'NestJS logo')

At this moment [NestJS](http://nestjs.com) is one of the best options out there. 

#### PRO's
- [Open source](https://github.com/nestjs/nest/blob/master/LICENSE) with [Enterprise support](https://enterprise.nestjs.com/)
- [Well documented](https://docs.nestjs.com/) & [Online courses](https://courses.nestjs.com/) available
- Wide scope (ie. standalone apps, web apps, good realtime support)
- Battle tested & large community
- Works with JS & TS
- Core features included (ie. security, persistence, API, etc.)
- Architectural patterns included (modularity, dependency injection, OOP patterns etc.) 
- Devops ready : testing, deployments, data migration, etc.
- Good choice for larger projects

#### CONS
- Feels overengineered (ie. a bit like Java / Spring)
- A steep learning curve
- Not ideal for small projects
